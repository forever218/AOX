# 国际化（i18n）· 一种语言一个发行版

- **状态**：已落地。文案阶段已完成 —— `src/` 与 `gui/src/` 里所有面向用户的字符串都是英文，
  并且都被 `t(...)` / `tf!(...)` 包住；中文词典在 `locales/zh.toml`（686 条）。
- **代码**：`src/i18n.rs`（运行时核心）、`build.rs::emit_lang`（注册表生成）、
  `locales/<码>.toml`（词表）。
- **一句话**：**语言在编译期就定死**（`AOX_LANG`），**英文是源语言**，非英文发行版只内嵌一份词表。

---

## 1. 一张图看懂

```
                        编译期                                        运行期
 ┌───────────────────────────────────────────────────┐       ┌──────────────────────┐
 │ AOX_LANG=zh                                       │       │ src/i18n.rs          │
 │   → build.rs::emit_lang                           │       │   t("Ready")         │
 │       • CODE    = "zh"                            │  ───►  │   → zh？查词表       │
 │       • CATALOG = include_str!("locales/zh.toml") │       │   → en？原样返回     │
 │   → 写入 $OUT_DIR/langs.rs                        │       │   → 查不到？回退英文 │
 └───────────────────────────────────────────────────┘       └──────────────────────┘
```

根 crate 的 `build.rs` 是**唯一**生成语言注册表的地方。GUI 没有自己的一份；它通过 lib 调用
`aox::i18n::t` / `aox::tf!`。所以在 `cargo` 命令行上设一次 `AOX_LANG`，就同时决定了
`aox.exe` **与** `aox-gui.exe` 的语言。

---

## 2. 三个设计决定

出自 `src/i18n.rs` 顶部的模块文档；它们是下面一切的 *为什么*。

1. **英文是源语言。** 代码里每个面向用户的字符串**本身就是**英文文案。这些字面量一身兼两职：
   既是 `en` 版的最终文案，又是其它所有语言词表要查的**键**。推论：加一门语言改**零行**源码
   —— 只加一个变体和一份词表，永远不动字面量。

2. **英文版零漂移。** 在源语言下 `t()` 原样返回实参，`tf!` 与 `format!` 逐字节等价。所以
   `AOX_LANG=en` 产出的输出与「i18n 存在之前」完全一致，一个现有测试都不用改。

3. **没有程序内切换。** 语言在二进制构建时就定死（`build.rs` 只 `include_str!` 那一份词表）。
   装英文版就是全英文 —— 界面、错误信息、系统提示词、工具描述一起切；装中文版就是全中文，
   而**其它**语言的字符串根本不会进入二进制。

## 3. `build.rs` 生成的注册表

`build.rs::emit_lang` 把下面这个很小的文件写进 `$OUT_DIR/langs.rs`，由 `src/i18n.rs` `include!`：

```rust
// Generated by build.rs, do not edit by hand.
pub const CODE:    &str = "zh";                     // AOX_LANG，已转小写
pub const CATALOG: &str = include_str!("…/locales/zh.toml");  // 源语言时为 ""
```

一张表记住规则：

| `AOX_LANG` | `CODE` | `CATALOG` | 结果 |
|---|---|---|---|
| `en`（默认） | `"en"` | `""`（不内嵌） | 字面量即文案；`t()` 是恒等 |
| `zh` | `"zh"` | `include_str!("locales/zh.toml")` | 查这一张表 |
| 其它 | 该码 | — | 若 `locales/<码>.toml` 不存在则**构建直接失败** |

重建触发条件都已声明，所以换一下变量就够 —— 不需要 `cargo clean`：

```rust
cargo:rerun-if-env-changed=AOX_LANG
cargo:rerun-if-changed=locales
cargo:rerun-if-changed=locales/zh.toml      // 实际用到的那份
```

**缺词表会让构建失败**，这是刻意的：「点了某门语言却没带词表」正是那种编译能过、只在运行时
表现为「满屏英文」的坑。

## 4. 怎么写一条可翻译字符串

```rust
use crate::i18n::{t, tf};                      // CLI（src/）
// gui/ 通过 lib 用同一批条目：
//   aox::i18n::t("…")   /   aox::tf!("…", …)

// 纯文本 —— 无占位符
println!("{}", t("Ready"));

// 带参数 —— 只认位置式 `{}`
println!("{}", tf!("Collapsed {} tool calls", n));
```

### 4.1 位置式 `{}` 规则（唯一要真正记住的一点）

`t()` 返回的是运行时字符串，所以不能在它上面用 `format!`（`format!` 要求模板是编译期字面量）。
于是 `tf!` 自己走模板，按顺序填**裸 `{}`**（`i18n::fill`）。它对宽度式和具名式**没有语法**：

```rust
tf!("score: {}", format!("{:.1}", x))     // ✅ 先格式化成字符串再作为参数传入
tf!("score: {:.1}", x)                    // ❌ {:.1} 不被识别 —— 会原样留下
tf!("{name} joined", name = n)            // ❌ 不支持具名占位符
```

词表里的值和源文必须**占位符个数**一致。参数不够时占位符会原样留下，而不是吃掉半句话
（看得见的 `{}` 就是「词表漏了一个参数」的线索）；参数多余则被忽略。

### 4.2 刻意不翻译的东西

`t()` 接收 `&'static str` —— **只吃编译期字面量**。运行时拼出来的东西原样穿过：

- 动态数据：插件名、文件路径、模型输出、工具实参；
- 由代码比较/匹配的协议或自产 token（如 `HOST_PREFIX`、`ATTACH_MARK`）；
- 钉住 UTF-8 / JSON 往返的测试夹具。

因此有两个文件仍**刻意**保留中文：`src/selftest.rs`（UTF-8 夹具字符串）与 `src/i18n.rs`
（`中文` 这个自称，见 §6）。它们是源码中仅剩的 CJK，§9 的漏网闸门预期正好报出这两个。

## 5. 词表格式 —— `locales/<码>.toml`

一张扁平 TOML 表，**英文键 → 译文**：

```toml
# locales/zh.toml  (English source -> Chinese)
"Ready" = "就绪"
"Collapsed {} tool calls" = "已折叠 {} 次工具调用"
```

键的规则 —— 词表要对齐的是**编译器眼中的字面量**，不是它的源码文本：

| 关注点 | 规则 |
|---|---|
| 外层引号 | **不**算键的一部分（代码里的 `"Ready"` → 键是 `Ready`） |
| 转义 | 键是**解码后**的运行时字符串：真换行，而不是 `\n` 两个字符 |
| 续行 | `\` 续行的多行字面量收成一个带真换行的键 |
| 占位符 | 位置式 `{}`，个数与源文**相同**；顺序可以不同 |
| 查不到 | 源文透出（可见线索；见 §7） |

当前中文词表是 `locales/zh.toml`（686 条）。源语言则**没有** `locales/en.toml` —— 内嵌一份
等于把另一门语言的字符串塞进英文版，`build.rs` 和一个单元测试都不允许（§8）。

## 6. `Lang` —— 码背后的枚举

`src/i18n.rs`：

```rust
pub enum Lang { #[default] En, Zh }         // En 是源语言
pub const SOURCE: Lang = Lang::En;

impl Lang {
    pub fn code(self)        -> &'static str { … "en" / "zh" }       // 落盘 / 命令行上的码
    pub fn native_name(self) -> &'static str { … "English" / "中文" } // 自称，永不翻译
    pub fn from_code(s: &str) -> Option<Lang> { … }                  // en、zh、cn；把 zh-CN / en_US 折叠掉
}
```

- `native_name` 一律**用该语言自身**书写、永不翻译：只读中文的人也必须能在英文诊断里认出「中文」。
- `from_code` 只取主子标签，所以 `zh-CN` 与 `en_US` 折叠成 `zh` / `en`。
- `lang()` 读 `langs::CODE`，码不认识就**当场 panic** —— 构建脚本已经证明词表存在，剩下唯一
  可能出错的就是「`build.rs` 和 `Lang::from_code` 脱节了」，必须说出来，不能悄悄回退英文。

## 7. 查找语义（`t` / `fill`）

- 源语言（英文）→ 入参**原样**返回（零漂移）。
- 其它语言 → 查表；**查不到回退英文源文**。宁可透出一句英文，也别显示空白或乱码 —— 而且透出
  来的那一句恰好就是「漏了哪条」的线索。`tools/check_i18n.py` 会把它们揪出来。
- 词表**格式坏**了不会拖垮程序：`map()` 打印
  `[i18n] failed to parse locales/<码>.toml: …` 并回退源语言。

## 8. 测试恒在源语言下跑

```rust
fn is_source() -> bool { cfg!(test) || lang() == SOURCE }
```

现有数百个测试都在断言英文输出（「结果里应包含某个词」）。因为 i18n 对源语言是恒等变换，
`cargo test` 下**一个都不用改** —— `cfg!(test)` 无视 `AOX_LANG` 把它们钉在英文上。release
构建不受影响（`cfg!(test)` 只在测试构建里为真）。

`src/i18n.rs` 里的单元测试钉住这些不变式，其中重要的是：

```rust
#[test] fn catalog_presence_matches_source() {
    if lang() == SOURCE {
        assert!(langs::CATALOG.is_empty());   // 源语言版不得内嵌任何词表
    } else {
        assert!(!langs::CATALOG.is_empty());  // 非源语言版必须内嵌一份
    }
}
```

这一个测试把 `build.rs`、`SOURCE` 和枚举绑在一起：英文版带了词表、或中文版没带词表，都会失败。

## 9. 验证一次构建

在源码里还留着少量刻意保留的 CJK 期间，闸门是**漏网扫描**：

```bash
python tools/check_i18n.py          # 摘要 + 「漏网」清单；有漏网/缺项则退出码 1
```

`tools/check_i18n.py` 扫 `src/**/*.rs` 与 `gui/src/**/*.rs`，跳过注释和 `#[cfg(test)]` 块，报出
每一个**没有**被 `t(...)` / `tf!(...)` 包住的 CJK 字面量。文案阶段完成后，预期输出就是 §4.2 那
两个刻意保留项（`selftest.rs` 夹具 + `i18n.rs` 的 `中文`），别无其它。当某条字面量本就是**数据**
而非文案时，可在同一行加 `// i18n-ignore` 注释就地豁免。

> ⚠️ 注意：这个工具的文档字符串和它那条可选的 `locales/en.toml` 交叉校验，来自更早的
> *中文源语言* 设计，如今已是遗留物。把它的**漏网清单**当信号即可。

每种语言来一次端到端冒烟：

```bash
AOX_LANG=en cargo run -- /demo      # 样例输出为英文
AOX_LANG=zh cargo run -- /demo      # 同一条命令渲染为中文
```

`AOX_LANG=zh` 下仍显示英文的，要么是真漏（去找 `{}` 个数不符、或键被多带了引号），要么是刻意
动态的值（§4.2）。

## 10. 如何新加一门语言 —— 三步

假设要加法语（`fr`）。

**① 加词表** `locales/fr.toml`，英文键 → 法文值：

```toml
"Ready" = "Prêt"
"Collapsed {} tool calls" = "{} appels d'outils repliés"
```

键必须与英文字面量**逐字符**一致（解码后、无外层引号）；占位符个数必须一致。要种这份表，产出
`zh.toml` 的那套工具同样可用：`tools/str_l10n.py dump <文件>` 列出英文字面量，`toml <acc.json> <out.toml>`
从累计的「英文 → 译文」表发射词表 —— 每门语言用**独立**的累计文件即可。

**② 让 `src/i18n.rs` 认识这个码** —— 加一个变体，并在三处各加一行：

```rust
pub enum Lang { #[default] En, Zh, Fr }
// Lang::code:        Lang::Fr => "fr",
// Lang::native_name: Lang::Fr => "Français",     // 用法文书写，永不翻译
// Lang::from_code:   "fr" => Some(Lang::Fr),
```

同时把两个枚举语言的测试（`lang_codes_roundtrip`、`every_lang_has_native_name` 里的
`[Lang::En, Lang::Zh]`）补上新变体，让它被覆盖。

**③ 构建：**

```bash
AOX_LANG=fr cargo build -p aox        # CLI
AOX_LANG=fr cargo build -p aox-gui    # GUI
```

这就是全部配方。若忘了第 ① 步，第 ③ 步会在构建期报错，并把配方再念一遍：

```
AOX_LANG=`fr` has no matching catalogue: …/locales/fr.toml
Adding a language takes three steps: ① locales/fr.toml; ② add a Lang variant
and a from_code arm in src/i18n.rs; ③ build with AOX_LANG=fr.
```

## 11. 如何构建某个语言的版本

`AOX_LANG` 默认 `en`，所以**不写就是英文**。把它放在 `cargo` 前面来选语言；它对本次调用里的
每个构建脚本都生效，而 `rerun-if-env-changed` 意味着换值会按需重编 —— 不需要 `cargo clean`。

```bash
# ── 英文（默认）─────────────────────────────────────────────────────
cargo build                      # 只构建 CLI（workspace 的 default-members = ["."]）
cargo build -p aox-gui --release # GUI

# ── 中文 ────────────────────────────────────────────────────────────
AOX_LANG=zh cargo build -p aox                          # CLI，debug
AOX_LANG=zh cargo build -p aox-gui --release            # GUI，release

# ── 两个二进制、release、同一门语言 ─────────────────────────────────
AOX_LANG=zh cargo build --release --workspace           # → target/release/{aox,aox-gui}.exe

# ── 直接跑，不产出具名 release ──────────────────────────────────────
AOX_LANG=zh cargo run -- /demo                          # CLI
AOX_LANG=zh cargo run -p aox-gui -- --demo              # GUI
```

说明。

- 单写 `cargo build` **只构建 CLI** —— workspace 的 `default-members` 是 `["."]`。要 GUI 得用
  `-p aox-gui` 或 `--workspace`。
- 语言由 **`aox` lib 的**构建脚本决定，而 GUI 链接了这个 lib，所以一个 `AOX_LANG` 同时覆盖两个
  `.exe`。
- release **安装包**（`tools/build_installer.sh`）内部跑 `cargo build --release --workspace`，并没有
  设 `AOX_LANG`，所以它当前产出的是**英文**包。要出中文安装包，就为整个脚本导出变量：

  ```bash
  AOX_LANG=zh bash tools/build_installer.sh
  ```

  （把 `build_installer.sh` / `.iss` 脚本参数化带上语言，从而 en 包与 zh 包可以并排产出，是一个
  可选的后续项。）

## 12. 坑

- **键是解码后的字面量本体，不带外层引号。** 把带引号的 token（如 `"Ready"` 连引号）喂给解码器
  会静默产出一个永远匹配不上的键 —— 英文版（恒等）把它藏住，只有中文版才暴露这个回退。
- **`tf!` 只认位置式。** `{:.1}` / `{name}` / `{:>9}` 必须先格式化成字符串参数（§4.1）。
- **要真换行，不要 `\n`。** 词表键里放 `\n` 两个字符，匹配不上解码为真换行的字面量。
- **多行与 `\` 续行的字面量手工 grep 极易漏。** 信任 §9 的漏网闸门，别信纯文本搜索。
- **改完翻译表要重新发射词表。** `locales/zh.toml` 是由累计表（`.workbuddy/l10n/acc.json`，经
  `tools/str_l10n.py toml`）生成的；只改累计表不重新发射，构建用的词表就是旧的。
- **别翻代码要比较的东西。** 用于相等判断、CLI 解析或持久化格式（`.jsonl`）的字符串是数据 ——
  只包呈现层，否则会改行为。
