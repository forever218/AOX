# 远端（AOXChat）会话：存储与上下文管理设计

> 状态：**待你拍板，未动代码**。拍完按 §7 的顺序落。

## 1. 先把事实摆正（避免方案建立在误解上）

**你看到的「Default」不是一个磁盘文件夹，是历史面板的一个分组。**

- 磁盘上：所有会话都是 `<app root>/.aox/history/<时间戳>.jsonl`，本地和远端的文件**在同一个目录里**。
  （`store::jsonl` 的规则：`dir_of(root) = <root>/.aox/history`）
- 面板里：`space::group()` 决定一条会话进哪个分组——
  显式 placement → `ws_full` → **`workplace` 记录的 root 命中哪个空间** → 都没有就进内置
  `builtin:default`（Default 这个名字来自 `Builtin::Default.label()`，不是目录名）。
- 远端为什么全进 Default：远端每一轮的 workplace 是 **default 层（= app root）**，
  命中不到任何自定义空间，于是整批落进 Default。
- 远端会话文件为什么会越来越多：`remote::worker` 里 **"One Agent per room"**——
  每个房间一个 `Agent`，第一次说话时懒创建一条会话文件。**这张 `room → Agent` 映射只在内存里**
  （`HashMap<String, RoomCtx>`），服务一重启就没了，于是每个房间下次说话又开一条新文件、
  上下文从零开始。会话标题是"第一条用户消息"，所以在列表里也看不出是哪个群。

结论：现在是"每次启动 × 每个房间 = 一条新会话"，既脏，又断上下文。

## 2. 两个问题必须分开看

| # | 问题 | 本质 |
|---|---|---|
| A | 面板里挤在 Default 里 | **归类**（一个 `space` 的落位规则） |
| B | 一个群对应几条会话、重启要不要续、什么时候开新的 | **生命周期** |

只做 A 等于把垃圾扫进另一个抽屉；只做 B 列表照样乱。建议一起做，但可以分两步上线。

## 3. 生命周期：一个房间一条，跨重启续上（推荐）

### 3.1 登记表

`.aox/remote.json` 的每个 pairing 增加一段：

```json
"rooms": {
  "<room_id>": {
    "conversation": "20261105-153012-a1b2",
    "name": "前端组",
    "opened_at": 1762300000,
    "turns": 12
  }
}
```

### 3.2 每轮开始前

```
查到 conversation 且文件还在  → agent.resume(id)      // 消息、用量、workplace 全接上
否则                          → agent.new_conversation()
                                第一轮落盘后把新 id 写回登记表
```

`Agent::resume` 已经做了全部恢复工作（`messages`、`usage_log`、`workplace` 的记录与"已持久化"标记），
远端这边不需要新的恢复代码，只要"决定 resume 哪一条"。

### 3.3 什么时候开新对话（三条，独立生效）

1. **手机说一声**：群里发 `/new`（现有远端斜杠命令里只有 `/model` `/key` `/cwd`，加一条），
   当前会话收尾，下一句开新的一段。
2. **上下文阈值**：`[remote] max_turns`（默认 50）或压缩预算用到 90%（现在 `provider.context_window=600k`，
   `max_tokens=32k`，预算 448k）→ 自动重开，并在群里说一句"上下文满了，另起一段"。
   不说的话人只会觉得"它怎么忘了刚才"。
3. **桌面手动**：历史面板右键这条会话 →「结束这段」（下次说话重开）。

### 3.4 标题

远端创建会话后立刻 `append_title("远端 · <房间名>")`。
列表里就是 `远端 · 前端组`，而不是 `@aox 帮我看看那个接口`。

### 3.5 保留

- 每房间只留最近 `[remote] keep_per_room`（默认 5）条；更早的按 `[history] keep` 一起裁。
- 裁剪必须**在创建新文件之前**做：`JsonlStore::create` 也是这个顺序（"先 prune 再建，否则新文件会把自己裁掉"）。

## 4. 归类：两种做法，推荐先做轻的那个

### 4.1 分组级（推荐，改动最小）

- `space.rs` 新增内置 `Builtin::Remote`：id `builtin:remote`、`root: None`、标签「远端」。
- 远端会话建好后 `Registry::place_conversation(id, "builtin:remote", None)`。
- 效果：面板多一个「远端」文件夹；Default 只剩本机对话；会话可以右键「移到」别的空间。

**谁写 `spaces.json`**：GUI（它已经是唯一写者，且持有刷新循环）。
worker 只发一个事件 `RemoteEvent::RoomConversation { room_id, conv_id, name }`，
由 GUI 那边 `place_conversation` + `save`。**不让 worker 自己 load-modify-save**——
两个线程整文件写 `spaces.json` 迟早互相覆盖。（见下面第 3 条。）

**磁盘不变**：文件仍在 `.aox/history/`。CLI 的 `/history` 照样能列出它们（按 workspace 扫描）。

**三个实现细节**（写在这里，省得到时候再想）：

1. 新增 `Builtin::Remote` 要同时改 `label()`、`ensure_builtins()`（顺序）和 `group()` 末尾的
   `retain`——**空分组会被丢掉**，所以「远端」只在该有会话时出现，这正好是想要的。
2. `spaces.json` 的 `VERSION` 建议 1 → 2：老版本读到 `"builtin":"remote"` 会解析失败并退回内置
   两个空间，结果是**用户的自定义分组在那一刻全丢**（文件本身没坏，但读不出来）。版本号抬上去，
   老版本是"明确拒绝"而不是"假装读懂了"，行为和现在这条规则一致。
3. 写 `spaces.json` 的只能是 GUI。worker 若自己 load-modify-save，和 GUI 的刷新循环撞上就是
   整文件互相覆盖。

### 4.2 目录级（真分开，但要先解耦）

想连磁盘都不混，就得让远端会话落到 `<app root>/remote/.aox/history/`。
`group()` 会自动按 root 成组，不用特殊规则。

**但**：`Agent::ensure_log` 里的 `at` 直接取 `workplace.active_root()`——
**"会话存哪"和"能写哪"现在是同一个值**。把 `at` 改成 `remote/`，等于"远端任务只能写 remote/"，
远端让你改项目代码就废了。

要干净地做，需要一处小接口变更：

```rust
// runtime.rs
pub history_root: Option<PathBuf>,   // 只有远端 worker 设，默认 None

// agent.rs::ensure_log
let at = self.rt.history_root.clone()
    .or_else(|| self.rt.workplace.active_root());
```

约 30 行，不碰 workspace 的判定逻辑。**这一步是可选的**，取决于你是否介意文件层面的混放。

## 5. 迁移与老文件

- 老文件**猜不出**属于哪个群（标题是 `@aox …`，多个群长得一样），所以不猜、不改写。
- 面板里右键「移到 → 远端」即可（`place_conversation` 现成），Default 里的老远端会话你自己搬一次。
- 新文件在 meta 里加 `kind:"remote"` + `room` + `room_name`，`group()` 加一条兜底：
  **即使 `spaces.json` 丢了或换机器**，也能按 meta 归回「远端」组。

## 6. 明确不做的事

- **不在桌面端"接手"远端会话继续聊**：它的输入在手机上，桌面插进去就是两边上下文打架。
  面板里点开 = 只读浏览（现有 `resume` 的只读路径）。
- **不按房间拆 workspace**：那会把远端任务的写权限关进一个小盒子，代价远大于收益。

## 7. 落地顺序

| 阶段 | 内容 | 量级 |
|---|---|---|
| S1 | 内置「远端」空间 + 房间会话登记 + 标题 + `/new` | 半天 |
| S2 | 阈值自动重开（轮数 / 预算）+ 每房间保留 N 条 | 半天 |
| S3 | `history_root` 解耦，文件真的挪到 `remote/`（可选） | 小半天 |
