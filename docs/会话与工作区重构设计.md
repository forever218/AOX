# 会话与工作区管理：重构设计（v2 · 不迁移）

> 状态：**R1 已实施**（2026-11-05）。项目未发布，不写任何老版本兼容代码；旧对话目录由你手动清掉，
> 程序里没有"找旧目录"的路径。

## 1. 现在到底有几套东西（事实地图）

| 概念 | 现在的存在形式 | 谁决定它 | 代码 |
|---|---|---|---|
| 会话文件 | `<root>/.aox/history/<时间戳>-<盐>.jsonl` | **该会话 workplace 的根** | `store/jsonl.rs::target_dir` |
| 会话 id | 文件名（时间戳+盐） | 创建时间 | `jsonl.rs::new_id` |
| 它属于哪个工作区 | 文件里**最后一条** `kind:"workplace"` 的 `root` | 那一轮的工作目录 | `jsonl.rs::read_summary` |
| 列表里的分组 | `.aox/spaces.json` 的 `Space.conversations` / `Space.root` | 注册表 + 会话记录 | `space.rs::group` |
| 模型能写哪 | 同一个 `workplace` 记录（tier + root） | 用户切的工作目录 | `workplace.rs` |
| 列表扫描范围 | `spaces.workspace_roots()` → `Store::set_workspaces` | 空间注册表 | `runtime.rs:187` |

一句话：**「会话存哪」和「模型能写哪」是同一个值**（`agent.rs::ensure_log` 的 `at = workplace.active_root()`）。
这就是乱的根源。

## 2. 六个问题

1. **选"工作目录 = 某项目"就把历史写进那个项目里。**
   `ensure_log` 在**第一次说话**时定位置，之后不搬——所以同一段对话的文件可能在项目 A，
   而它最后记录的 workplace 是项目 B。`workplace/<项目>/.aox/history/` 就是这么来的。
2. **文件名没有身份。** 看不出是谁、哪个工作区、本地还是远端。
3. **归属要读全文才知道。** 列表要分组就得把每个文件从头扫到尾找 `workplace`，再和
   `spaces.json` 对一次；两个真相源任何一个丢，分组就散。
4. **列表成本 = 目录数 × 文件数 × 全文扫描**，而这些目录大多数是空的。
5. **删工作区不会删它的历史。** 文件藏在那个项目的 `.aox/history` 里，之后既不显示也不受管理。
6. **远端没有位置。** 每个群一条会话，却按"默认工作区"落进 Default 分组。

## 3. 目标：三层彻底分开

| 层 | 是什么 | 存在哪 |
|---|---|---|
| **会话库** | 所有对话文件 | `<app root>/.aox/conversations/`，**唯一一个目录** |
| **空间** | 列表里的分组 | `.aox/spaces.json`（纯元数据） |
| **工作目录** | 这一轮模型能写哪里（沙箱） | 会话文件里的 `workplace` 记录（**语义不变**） |

关键简化：**`Space.root` 从"存储位置 + 沙箱根"降级为"这个空间里新会话的默认工作目录"。**
它不再决定任何文件落在哪。

## 4. 磁盘布局与文件格式

```
<app root>/
  .aox/
    conversations/                 ← 唯一的会话库
      20261105-153012-a1b2.jsonl
    spaces.json                    ← 分组（内置三个）
    memory/  tmp/  run/  backup/ …
  workplace/<项目>/                ← 只剩交付物，不再有 .aox/history
```

文件名和 id 都不变（所有调用点只认 id）。归属写进首行 meta：

```json
{"kind":"meta","v":3,"id":"20261105-153012-a1b2","created":1762300000,
 "model":"deepseek-chat","origin":"local","space":"builtin:default",
 "room":{"id":"01M6…","name":"前端组"}}
```

- `origin` = `local` / `remote`；`space` = 创建时的归属（用户"移到别的空间"只改 `spaces.json`，
  注册表始终是"人把它放哪"的唯一真相，文件里的只是出厂记录）。
- `v` 留着做格式标记，但**代码里没有按版本分支**——不为不存在的旧格式写兼容。

## 5. 切换步骤（一次性，无迁移代码）

代码侧（R1 全部在一个提交里）：

1. `Store` 接口去掉 `at` 参数：`create(model)`、删掉 `set_workspaces` / `history_dir_for(at)` /
   多目录 `find` / `extra` 字段。**会话库只有一个目录。**
2. `JsonlStore::home` 改成 `<app root>/.aox/conversations`。
3. `agent.rs::ensure_log` 不再问 workplace；`store` 自己知道往哪写。
4. `workplace::ensure_started` 不再创建 `.aox/history`（只留 `tmp/ memory/ workplace/`）。
5. meta 写入 `origin / space / room`；`Agent` 与远端 worker 各自填。
6. `Runtime` 去掉 `store.set_workspaces(spaces.workspace_roots())` 这处耦合
   （`spaces` 仍保留，但只给 GUI 用）。

数据侧（**一次性手动，不进程序**）：

```bash
mkdir -p .aox/conversations
mv .aox/history/*.jsonl .aox/conversations/
mv workplace/*/.aox/history/*.jsonl .aox/conversations/   # 如果存在
rmdir .aox/history workplace/*/.aox/history               # 空的就删
```

我会在切换时执行，并确认条数对得上（当前 `.aox/history` 27 个文件）。
之后程序里**没有**任何"找旧目录"的代码路径。

## 6. 列表性能

- 单目录 + **摘要缓存**：`HashMap<id, (mtime, len, Summary)>`，`list()` 先 `stat`，没变就用缓存。
  不改标题、不新建时命中率接近 100%。
- 冷启动全扫一次；200 条 × 1 个目录应 < 50 ms。
- 上限仍是 `[history] keep`（默认 200）。

## 7. 空间管理

内置三个，顺序固定：

| id | 名字 | root | 说明 |
|---|---|---|---|
| `builtin:default` | **本机** | app root | 本机对话默认落这里 |
| `builtin:remote` | **远端** | 无 | 手机上发起的对话，按群分组 |
| `builtin:full` | **完整访问** | 无 | 只有"不限制"这一种语义 |

- 新建空间两种：**绑目录**（= 现在的工作区，决定新会话默认在哪个目录干活）；
  **纯标签**（`root = None`，只是分组——远端就是这么用的）。
- 删除空间 = 解散分组，不动文件。
- 会话行：标题 + 时间 + badge（`远端 · 前端组` / `工作目录：项目A`）。

## 8. 配置

```toml
[history]
enabled = true
keep = 200
```

不新增 `[history] dir`：位置固定，多一个配置项就多一条"用户配错、我们猜"的路径。
真要换位置，改一个常量即可。

## 9. 分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| **R1** | 会话库单一化 + 接口去掉 `at` + meta 三字段 + 手动搬文件 | `/history dir` 只报一个目录；27 条对话都在；`workplace/*/.aox/history` 为空；远端任务写进会话库而不是项目里 |
| **R2** | 摘要缓存 + 空间改名（本机/远端/完整访问）+ 纯标签空间 + 会话 badge | 冷启动列表 <50ms；分组正确；远端不再进 Default |
| **R3** | 远端房间会话登记（`docs/远端会话存储设计.md` 的 S1/S2：跨重启续 + `/new` + 每群保留 5 条） | 重启后同一群还是同一段 |

R1 会**删掉一批代码**（多目录扫描、`set_workspaces`、`history_dir_for`、`extra`），
这是这次重构真正的收益：`Store` 接口里最后一个路径参数消失。

## 10. 风险

- **R1 之后老对话在新代码里可见性取决于那次手动 `mv`** —— 所以搬完要核对条数（我会在验收里给出
  `ls | wc -l` 的前后对比）。
- **中途切换工作目录不再影响文件位置**：这会让"文件在 A、记录说 B"这类错位从根上消失，
  但也意味着**同一段对话只会有一个文件位置**，不会再散。
- `workplace/*/.aox/history` 若被别的工具占用（不太可能），`rmdir` 会失败——留着即可，
  程序不再读它。

## 11. 需要你点头的三件事

1. 目录名定 `.aox/conversations`（我按这个写）。
2. 内置空间叫「本机 / 远端 / 完整访问」。
3. 顺序：先 R1（含手动搬 27 个文件）单独提交验收，再做 R2/R3。

## 12. 实施记录（R1，2026-11-05）

落地的东西，和上面设计逐条对应：

| 设计项 | 实现 |
|---|---|
| 会话库单一化 | `store::jsonl::DIR_NAME = "conversations"`；`JsonlStore { root, home, keep }` |

| 内置空间 | `Builtin::Remote`（`builtin:remote`）；`Default` 的显示名改走新词条 `Local`=本机 |

`workplace::HISTORY_DIR` 常量；`space::Registry::workspace_roots`（改名 `roots`，只用于目录树）。
