01一次调用的全景

竖轴是时间，向下是一个 while 迭代。左侧蓝色是循环骨架（写死在 StandardLoop::run 里），右侧是六个可以替换 / 插入的能力。虚线红框是尚未存在的 文件系统守卫 —— 它计划插在第 8 步之前。

上半段 S1–S11 是循环的每一次迭代（拿到回复为止）；下半段 T0–T8 是同一个循环里的一个 for —— 模型一次返回 N 个 tool_calls 就走 N 遍，走完再回到 S1。 右侧紫色是已实现的能力面，红色虚框是尚不存在的守卫（详见第 3 节），此后各步在第 2 节的表里逐行展开。

05「不改变循环」是怎么做到的

这五条不是口号，每一条都对应一个可检查的机制。撤掉对象 ≠ 改循环 是它们共同的形式。

默认空链

Hook 的五个方法全部带默认空实现，[hook] 为空时链是空的。 空链的每次调用退化成「查一下长度然后返回」，五个插入点全部是 no-op。

钩子拿不到裸 Vec

before_request 只能往 Request::inject 里放东西，由循环经 Agent::push_message 入列。messages 的唯一写入口同时写文件 —— 交出裸 Vec 等于开一个「内存里有、文件里没有」的后门。

快照而非持锁迭代

钩子点每次调用先在读锁下克隆一份 Arc 快照再迭代。因为 std::sync 读锁不是 Send，跨 await 持着它整个 future 就失去 Send。 空链克隆不分配 —— 默认配置下这条路径零开销。

只有一条授权判定路径

组件在 [contributes] caps 里声明能力，宿主把它原样转进 Policy::level_for，而不是新造一套。规则：插件工具 + caps 非空 ⇒ Ask， 位置钉在「用户显式 override」之后、「类别默认」之前。

组件可降级是硬要求

ComponentHook 的每个出口都有兜底值：组件不在 / 10s 超时 / 返回垃圾 / 认不出的 verdict —— 一律 Pass。失败记在共享的 Arc<AtomicU64> 上， /hook 看得见（静默降级，但不静默消失）。

循环本身也是可替换的

StandardLoop 是原 Agent::run_loop 的逐语句搬运。 [loop] impl 写了认不出的名字启动即报错，不静默退回 standard —— 与 [store] backend 同一条原则：写了却不生效最难查。

06三种视图下的同一件事

同一次 fs_read，在三个地方各留下一条轨迹。它们不是同一个字节： preview 与送模型的正文走两套独立阈值，而落盘那份与送模型的那份同源。

这也是 6a/6b e2e 的一条教训：断言要断内容 + 确切措辞，且要先确认调用次数 —— 测试夹具自己也会截断被测数据（history_lines() 截 120 字会把 after_tool 的尾部印记切掉）。

07这条流水线上的已知缺口

不是流水线的 bug，是这条链路没有被覆盖到的地方。守卫排第一不是因为它最复杂， 而是因为可扩展性这条轴推得越远，它越紧急。
